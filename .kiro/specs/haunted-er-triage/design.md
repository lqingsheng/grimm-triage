# Design: Grimm Triage

## Architecture
Static single-page app. `triage.js` (pure engine) ← `app.js` (DOM) ← `index.html`. `cases.js` is data. No server of our own; the optional accounts (task 22) use Supabase as a hosted backend, and the app works fully without it.

## Engine (ESI v4 decision points)
- A: life-saving intervention / unresponsive / critical vitals → 1
- B: high risk, altered mental status, severe pain → 2
- C: count resources → 0 = 5, 1 = 4, >= 2 → check D
- D: danger-zone vitals (adult: HR > 100, RR > 20, SpO2 < 92) → 2, else 3
- Pediatric danger zones (to implement): <3 mo HR >180 RR >50; 3 mo–3 y HR >160 RR >40; 3–8 y HR >140 RR >30; SpO2 < 92 for all.
Output: `{ level, reasons[], dangerZone, missing[], provisional }`. Errors: `TypeError` with all field messages joined.

**Missing vital signs (task 17, clinical-safety rule 7):** on the Triage Desk, HR, RR, SBP, SpO2 and temperature may be `null` (not measured). Only explicit `null` counts: `undefined` or `NaN` is still an error. Points A and B use only measured values, so a missing value never triggers level 1 on its own. At D (2+ resources), a measured danger-zone value gives ESI 2 as before. Otherwise a missing HR, RR or SpO2 gives a **provisional** ESI 2, with the reason "danger-zone vital signs could not be checked: when in doubt, choose the more urgent level". ESI 4 and 5, and missing SBP or temperature, never change the level. `missing` lists the null vitals in the order hr, rr, sbp, spo2, tempC. The calculator treats a blank field as missing, and offers an optional reason per vital (refused, agitated or uncooperative, no equipment, measurement failed, other). It shows a warning (`#calcWarning`, `role="note"`, referenced by each missing input's `aria-describedby`) that lists what is missing and says "Measure as soon as possible and re-triage.", and a "Provisional" tag next to the badge. The game's cases always have all five vitals.

## Scoring
`scoreGuess(guess, truth)`: exact 100, ±1 = 50, else 0; under-triage subtracts 25 (floor 0). Rationale: under-triage is the clinically dangerous error.

## Game flow
Night start → plan the night → for each: render card → player picks level → reveal (badge, reasons, points, effect) → next → shift report.

**Nightly plan (task 14, `src/night.js`, pure):** `planNight(CASES, { random, avoid })` draws 3 cases per ESI level (15 per night) and shuffles them. It skips last night's ids, which `app.js` stores in localStorage under `grimm-triage-last-night`. Avoided cases come back only if a level has too few fresh ones; with 12 per level that never happens. Each drawn case is then instantiated: every ranged vital is drawn inside its `variants.vitals` range (whole numbers; temperature to 0.1 °C), and one of the story's openings is picked (its own first sentence or one of 2–3 alternatives, in both languages). One injectable `random` drives all of this; the app passes `Math.random`, and tests pass the seeded `mulberry32(seed)`.

**Storylines (task 21, `src/storylines.js` and `src/night.js`, pure):** a storyline is `{ id, title: { en, 'zh-CN' }, cases: [firstId, secondId], epilogue: { en, 'zh-CN' } }`. Its cases sit in `CASES` like any other, flagged `storyline: '<id>'`. `drawNight` draws the regular night exactly as before from the cases without the flag. Then, if at least one storyline is eligible (all its cases in the bank, none in `avoid`, which is how "not used last night" is defined), one more `random()` call decides (`< STORYLINE_CHANCE`, 0.5), and a second picks the storyline. `addStoryline(night, linked, random)` removes one random regular case of each linked case's level, picks a gap of 2–5 patients and a first position from patient 2 onwards, and inserts the pair in order. When nothing is eligible no extra random number is used. In the game, `linkFor(night, index)` finds the earlier patient for the later card, which gets a static `.storyline-badge` paragraph (title and "same incident as patient N"; the 🔗 is `aria-hidden`) referenced by the card's `aria-describedby`. The first card has no badge. `storylineReport(answers)` returns the storyline, its patients with their numbers and under-triage flags, and `underTriaged`. The report shows it as an opaque `<section>` between the missed cases and the lesson, with the epilogue and the general rule "Triage the patient in front of you, not the story."

**ESI v4 lesson (task 15, `src/lesson.js`, pure):** `lessonHtml({ tr, badge, missed, open })` builds a `<details>` section that the report places below the missed cases and above "Start a new night". It is closed by default and open when the night had an under-triage; after a language switch it keeps the player's own open or closed choice. Contents: the four decision points as an ordered list; resource and non-resource lists; a danger-zone `<table>` (`<caption>`, `<th scope="col">` and `<th scope="row">`) whose numbers come only from `ADULT_DANGER` and `PEDIATRIC_DANGER`, so it cannot disagree with the engine; "Where your shift went wrong"; the level-1 simplification note; the source line. `decisionPointFor(result)` in `src/shift.js` maps a `triage()` result to its decision point: ESI 1 is A; ESI 2 is D if the reason is danger-zone vitals with 2+ resources, otherwise B; ESI 3–5 is C. `app.js` stores the step with each answer, and the missed-case list shows it as a "step X" tag. The lesson is an opaque card inside `.report` (above the stains) with no animation or transition. All text is in `src/i18n.js` in both languages, written in our own words.

**Triage Desk inline help (task 16, `src/deskhelp.js`, pure):** in `index.html` the five judgement fields (pain, expected resources, high-risk complaint, life-saving intervention, new confusion / lethargy) are each wrapped in `.field[data-field]`. `app.js` inserts an ⓘ button there (`aria-expanded`, `aria-controls`, translated `aria-label`, 44 px target) and a panel under the field (`role="region"` labelled by its `<h3>`, `hidden` when closed). An open field spans the whole form row. Escape inside a panel closes it and returns focus to its button. After a language switch the help is re-rendered and keeps its open panels and ticked boxes. The resource help is a checklist built from `RESOURCE_COUNTS` and the `lesson.counts.*` strings, followed by the `RESOURCE_NOT` list. `countResources(ticked)` counts each type once, with a complex procedure counting 2. Ticking a box writes the total into the number field, which stays editable. All text is in `src/i18n.js` (`help.*`) in both languages, in our own words: no links, images, faces artwork or handbook text, and no animation.

**Score maximum:** `summarizeShift` returns `max` = 100 × cases played (1500 for a full night). The report shows each missed case's drawn vitals next to its teaching point.

**Optional accounts (task 22):** `config.js` → `supabaseConfig()` gives `{ enabled, url, key }`; `app.js` creates `createAccountService({ config })` and calls `mountAccounts()` only when it is enabled, which unhides the `[data-account-feature]` elements (header slot, notice, Progress and Leaderboard nav buttons, footer line). Sign-in: `beginSignIn(provider)` stores a 64-character PKCE verifier (`grimm-triage-pkce`) and navigates to `/auth/v1/authorize?provider=…&redirect_to=<this page>&code_challenge=…&code_challenge_method=s256`; on the way back `init()` exchanges `?code=` at `/auth/v1/token?grant_type=pkce`, stores `{ access_token, refresh_token, expires_at, user_id, provider }` (`grimm-triage-session`) and removes the code from the URL with `history.replaceState`. PKCE keeps tokens out of the URL, which the Umami script may see. The token is refreshed 60 s before expiry (timer, and before any request); a rejected refresh token ends the session, a network failure keeps it. Then the profile is read or created with a generated nickname, and queued results are sent. When the shift report opens, `saveNight()` stores the row in this device's history (`grimm-triage-history`, for the guest Progress panel), queues it (`grimm-triage-pending-results`, entries `{ userId, row }`) and sends the queue; a row the database rejects (400 other than the daily limit) is dropped and the player is told, anything else is retried on the next load. Progress comes from `rpc/my_progress` when signed in, else from the device history. The leaderboard comes from `rpc/leaderboard`. The account dialog is a native `<dialog>` (Escape closes, focus returns to the header button). Database: `profiles (id → auth.users, display_name check valid_display_name)` and `results (user_id default auth.uid() → profiles, score, correct, under_triage, over_triage, storyline, played_at, created_at)`, both with RLS and column-level grants; checks follow `scoreGuess()` (score multiple of 25, 100 × correct ≤ score ≤ 100 × correct + 50 × over + 25 × under, counts sum to 15); a before-insert trigger enforces 30 rows per 24 h and a sane `played_at`.

## Data model (case)
`{ id, name, emoji, story, patient, expectedLevel, teachingPoint, zh, variants }` — `patient` matches the engine input (the case's typical values); `expectedLevel` is the author's intended ESI level, checked against `triage()` by a unit test. `variants.vitals` gives a `[low, high]` range for hr, rr, sbp, spo2 and tempC (and optionally pain); every value inside must give `expectedLevel` (P8). `variants.openings` lists optional `{ en, zh }` alternatives for the story's first sentence. Stories and teaching points quote thresholds, never the patient's own values.

Case bank: 71 cases. 61 regular cases (12 per ESI level, 13 at ESI 2 after the clinical review moved the staggered paracetamol overdose up), 18 pediatric (at least 2 in each age band: < 3 months, 3 months–3 years, 3–8 years). Plus 10 storyline cases (task 21, optional `storyline` field), only drawn in pairs: ESI 1 ×3, ESI 2 ×3, ESI 4 ×2, ESI 5 ×2, 2 of them pediatric.
Portraits live in `src/portraits.js` as `PORTRAITS[id] = { label, art }` (inline SVG shapes only, `aria-label` from `label`); `test/portraits.test.js` checks every case has one.

## Haunting effects
`app.js` adds `fx-under` or `fx-correct` to `#game` after an answer and removes it on the next case; `fx-under` also puts `haunted` on `<body>` for the screen vignette. All motion is CSS keyframes. Correct answers get the candle flare (`fx-correct`).

Under-triage (`fx-under`, task 13). Decorative only (`aria-hidden`), inline CSS/SVG, no images and no gore:
- **Flicker:** a dark red overlay (`.fx-dim`) dims the panel twice in 1 s. It is an overlay, not a `filter`, so `#game` never becomes a stacking context.
- **Drips:** 12 streaks, 4–14 px wide with a glossy highlight (`DRIPS` in `src/haunt.js`). Each streak grows from the top edge, its drop falls to the bottom and a scalloped pool rises along the bottom edge. After 4 s the streaks recede to 25% opacity (0.8 s fade) so the story and vitals are readable while the player studies the feedback; the pool stays at full strength.
- **Handprint:** inline SVG on the right side, slapped on and smeared down; recedes to 25% with the drips.
- **Vignette:** fixed, full screen, dark red (`--vignette`), one pulse per second for 3 s, starting at 1.1 s after the flicker has ended, peak opacity 0.55 (`heartbeat 1s … 1.1s 3`).
- **ECG:** a trace across the top of the card, starting at 1.1 s with the heartbeat: three beats, the last one weak, then a flat line.
- **Portrait:** desaturates for about 2 s while the eyes glow red (`eyeGlowSvg()`; eye centres in `PORTRAITS[id].eyes`).
- **Escalation:** one dried stain per under-triage this night (`stainLayout(count)` in `src/haunt.js`, deterministic). Older stains grow by 14 px per later under-triage, capped at 160 px. The stains persist through the night and the shift report, and only "Start a new night" clears them.
- **Sound (optional):** OFF by default. The header "Sound effects" toggle (`aria-pressed`, stored as `grimm-triage-sound`) turns it on. `src/sound.js` synthesises three lub-dub heartbeats in step with the vignette, then a 960 Hz flatline beep, using Web Audio oscillators only (no audio files, no recordings). The master gain is 0.25 or lower, and the sound stops within 50 ms on the next case or when toggled off. The toggle is hidden when Web Audio is unavailable.

Rules:
- **Flashes (WCAG 2.3.1):** only the flicker (peaks at 0.15 and 0.55 s) and the vignette (peaks at 1.25, 2.25 and 3.25 s) change the brightness of a large area. That makes at most 2 flashes in any 1 s window. WCAG allows 3; we hold to 2 because red flashes are the riskiest kind. The vignette colour is not a "saturated red" (R/(R+G+B) < 0.8). No haunting animation loops. `test/haunt.test.js` recomputes all of this from `styles.css`.
- **Readability:** the stacking order is stains (1) < case text (2) < effects and ECG (3) < vignette (5) < level buttons, feedback and Next (6). During `fx-under` the feedback gets a near-opaque backing. Text tokens keep at least 4.5:1 contrast over `--stain`.
- **Reduced motion:** under `prefers-reduced-motion` the effect layer, vignette, ECG and eye glow are `display: none` and the portrait does not animate. The player sees only the static stains (no grow transition), the panel tint and the `.fx-note` text in the `aria-live` feedback.

## Theme tokens
`--bg --ink --blood --ecto --pumpkin --l1..--l5`. Motion only via CSS; disabled under `prefers-reduced-motion`.

## Testing strategy
- Unit tests for each decision point and every case's expected level.
- Property tests: range/explanation (P1), determinism (P2), level-1 triggers (P3), monotonic safety for high-risk (P4), SpO2 (P5), resources (P6), pediatric thresholds (P7), missing vitals (P9: a missing vital is at least as urgent as any measured value that is not itself a level-1 trigger), case variants (P8: any vitals drawn from a case's ranges give exactly its expectedLevel; if not, narrow the range, never the engine), storylines (P10: for any seed and last-night list, 15 unique patients, 3 per level, and each storyline either whole, in order, 2–5 patients apart and not patient 1, or absent, and never one used last night).
- Storylines (`test/storylines.test.js`): data in both languages, every listed case flagged and every flagged case listed, about half of nights with a storyline, all storylines and gaps reachable, no repeat of last night's storyline, the regular draw unchanged without one, the badge text and the report section in both languages, and no animation.
- Case bank (`test/cases.test.js`): size and balance, coverage of the requested presentations, range validity, openings, no quoted vital values, and a boundary grid that checks every range end and engine cut-off combination for every case (the deterministic twin of P8).
- ESI lesson (`test/lesson.test.js`): `decisionPointFor` matches the rule that fired for every case and drawn variant; the table numbers equal the engine's thresholds, with none hard-coded; every lesson key exists in both languages; markup and accessibility (headings, lists, scoped table headers, no animation); placement and auto-open in the report.
- Triage Desk help (`test/deskhelp.test.js`): every `help.*` key in both languages; the checklist count for all 512 tick combinations (complex = 2, each type once); the checklist uses the lesson's keys and strings; buttons carry `aria-expanded` and `aria-controls` pointing at their panel; no links, images or animation.
- Missing vital signs (`test/missing.test.js`, `test/desk-missing.test.js`, P9 and P9b): every case has all five vitals; only `null` means not measured; each of rules 2–5; an exhaustive grid of P9 over every engine cut-off and age band; the form markup, parsing, warning, provisional tag, strings and shared help/lesson line.
- Nightly draw (`test/night.test.js`): 3 per level, no repeats from the previous night, top-up when a level runs short, determinism with a seeded random, shuffled order, every case reachable, and no use of `Math.random`.
- Visitor analytics (`test/analytics.test.js`): `track()` is a no-op without `window.umami`, with `?seed=` and with Do Not Track, and never throws; payloads keep only the allowed key and valid values; every `track()` call in `src/app.js` sends one allowed property; index.html has the exact Umami tag and no other third-party resource; the service worker ignores Umami requests; the demo recorder blocks the script.
- YouTube statistics (`test/youtube-stats.test.js`): API URL without a key; parsing (hidden likes are `null`, missing statistics, missing video and API errors are clear errors); append, file shape and trimming to the newest 1000; key redaction; the script exits non-zero without a key; the workflow's schedule, permission, commit message and push target; `vercel.json` content.
- Accounts (`test/accounts.test.js`, mocked fetch only): OAuth URL and PKCE challenge, redirect and session parsing (no email stored), headers, refresh timing, single-flight refresh, 401 retry, sign-out; display names (Chinese and other scripts accepted, markup, emoji, underscores and bad lengths rejected); payload fields and seeded nights; the retry queue (offline, expired session, other accounts, rejected rows, daily limit); empty config (no request, no storage change, all account markup hidden); Progress and Leaderboard rendering in both languages with escaped names; the service worker ignoring Supabase; static checks of the migration (RLS on every table, constants, function search paths, delete only the caller, leaderboard columns).
- Haunting effect (`test/haunt.test.js`): drip and stain layout, flash count and vignette colour parsed from `styles.css`, layer order, reduced-motion rules, eye positions, and the sound schedule run against a fake `AudioContext`.
